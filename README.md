# Supplementary materials: dataset reproducibility

The audiobooks and literary texts used in this work are protected by the copyright of their
rights holders — the source audio and text files themselves are **not published** as part of the
resulting dataset. To make the results reproducible, the following are published here:

1. **The code of the complete data collection/processing pipeline** (`scripts/`, stages 1.1–1.6,
   see below) — copies of the actual scripts from the main repository, frozen as of publication.
2. **Dataset metadata** (`manifest_public.csv`, generated by `build_public_manifest.py`) — the
   title of the work, the narrator, the timecodes of fragments in the source recording, the
   extracted textual descriptions, plus checksums of the source audio files for verifying
   correspondence.
3. **LLM setup and configuration** used for the extraction step (stage 1.2) — see
   [`LLM_SETUP.md`](LLM_SETUP.md): exact model checkpoint, `llama-server` launch command, and the
   generation-config decisions (thinking budget, structured output, post-filtering) that shaped
   the extracted `speech`/`description` pairs.

This allows researchers who have legal access to the corresponding recordings (including via the
public knigavuhe.org links in `manifest_public.csv`) to reproduce the training set themselves —
download the audio, cut it at the given timecodes, verify the `sha256` against the published
value, and obtain the same 89015 pairs (audio fragment, text, manner description) used for
training.

## Dependencies

Pinned Python package versions (the exact versions used to produce `manifest_public.csv`,
Python 3.12.3) are listed in [`requirements.txt`](requirements.txt): `pip install -r
for_paper/requirements.txt`. Two stages have non-pip requirements: stage 1.2
(`03_extract_speech_fragments.py`) needs a running `llama-server` endpoint (see
[`LLM_SETUP.md`](LLM_SETUP.md)); stage 1.4a (`06_cut_audio_fragments.py`/`07_verify_fragments.py`)
needs the `ffmpeg` and `flac` command-line binaries on `PATH`.

## Data collection pipeline (stages 1.1–1.6)

Sources (not included in this package — only the processing code is): digital editions of the
books (`.epub`), knigavuhe.org (audiobooks, ASR transcripts with word-level timings). For more
detail on the source data layout, see the root `CLAUDE.md` of the main repository.

| Stage | Script(s) | What it does |
|---|---|---|
| 1.1 | *(outside this package, `scrapping/`)* | downloads texts/audio per the book registry |
| prep for 1.2 | `01_sample_books_for_tfidf.py` | train/holdout book sampling for the TF-IDF+POS pre-filter |
| prep for 1.2 | `text_utils.py`, `pos_filter.py`, `tfidf_pos_hybrid_filter.py` | shared pre-filter modules (no number — plain library modules, imported by name from steps 02/03/05, not a standalone pipeline step) |
| prep for 1.2 | `02_train_tfidf_pos_hybrid.py` | trains the hybrid TF-IDF+POS pre-filter — skips clearly non-dialogue text chunks before the expensive LLM call |

| 1.4b | `10_join_features.py` | joins text fragments + acoustic features + text axes |
| 1.4b | `11_derive_scores.py` | produces the hard/soft quality filters (exact thresholds — see the section below); this is the functional equivalent of the WER filtering mentioned in the project's general plan |
| 1.4b (input to 11) | `12_narration_baseline.py` | neutral acoustic baseline per (narrator, book) pair — the reference used when deriving soft scores |
| — | `13_anonymize_descriptions.py` | strips character names from `description` (needed only for training the text encoder, so the model doesn't shortcut manner-of-speech via character-name recognition; unrelated to the metadata anonymization done for this publication) |

Run order — strictly by number (`01` → `02` → ... → `15`); the diagnostic
`05_check_text_audio_mismatch.py` is run as needed, not part of the main chain.

**A note on numbering**: files here have been renumbered from scratch (01–15), strictly in
execution order, specifically for this standalone package — the numbering does NOT match the
numbering of the identically-named scripts in the main repository (there, numbering runs across
the whole project's scripts, including steps unrelated to data collection, which is why the
original numbering had gaps). Docstrings/example run commands inside the files themselves may
still reference the old numbers from the main repository (e.g. `python scripts/07_derive_scores.py`)
— that's not a typo, just a trace of the file's origin; go by the file's actual name in this
folder, not the text inside its docstring.

## Train/val/test split parameters

The published `split` column was produced by `15_assign_reader_split.py` with its **default
arguments**: `--seed 0`, `--train-ratio 0.8 --val-ratio 0.1 --test-ratio 0.1`. The split is
reader-disjoint (each narrator's fragments all go to one split) and gender-balanced — a greedy
largest-processing-time-first (LPT) bin-packing by total narration hours, run **separately** for
male and female narrators, each targeting the same 80/10/10 ratio within its own group. With 37
narrators this reproducibly hits the target ratios exactly (not an approximation): female
25.8/3.2/3.2h (80.0/10.0/10.0%), male 91.3/11.4/11.4h (80.0/10.0/10.0%); overall train 117.1h/17
narrators, val 14.6h/9 narrators, test 14.6h/11 narrators. Re-running the script with these exact
arguments on the same input (`manifest.csv` before the `split` column is added) reproduces the
same `split` assignment.

## Explicit filtering thresholds

Exact criteria from `11_derive_scores.py` (default values as of publication — these are the ones
that produced the final **89015 fragments / 146.4 hours**):

**Hard filters** — a fragment enters the dataset only if all four conditions are false:

```
~junk_any_hard & ~junk_badmatch & ~junk_few_words & ~junk_few_asr_words
```

| Flag | Condition | Threshold/argument |
|---|---|---|
| `junk_zerodur` | `duration_s <= 0` | — |
| `junk_toolong` | `duration_s >= 60.0` | `--max-dur` (over-capture) |
| `junk_tooshort` | `duration_s < 0.40` | acoustic junk |
| `junk_any_hard` | `junk_zerodur ∪ junk_toolong ∪ junk_tooshort` | — |
| `junk_badmatch` | `match_distance_norm >= 0.4` | `--max-dist` |
| `junk_few_words` | `speech` has `<= 3` words | — |
| `junk_few_asr_words` | `n_words_matched <= 3` | — |

**Important caveat**: `junk_nonspeech` and `junk_silence` (acoustic flags also present in
`scores.csv`) are **deliberately excluded** from `junk_any_hard` — they were judged to be
unvalidated acoustic heuristics (on par with `junk_truncation`/`junk_flatness_soft`) and are kept
only as reference columns; they do not enter the hard filter.

**Soft buckets** (`manner_bucket`, reference-only manner metadata, NOT part of the hard filter):
- `confirmed` — `loudness_agree >= 0.5` (`--confirm-sigma`): the description text deviates from
  the narrator's neutral baseline (`12_narration_baseline.py`), and the fragment's acoustics
  confirm it.
- Other buckets (`neutral`, etc.) — see the logic in `11_derive_scores.py`/`09_extract_text_axes.py`;
  not fully duplicated here, only the numeric thresholds above are given.
